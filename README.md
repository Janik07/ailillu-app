# Ailillu на React

Рабочая демо-версия гостевого приложения Ailillu: Vite, React 19, TypeScript. Сайт: https://janik07.github.io/ailillu-app/ Заведения, меню, цены, столы и фото настоящие, из API ailillu.kz. Заказ, SMS, Kaspi и вызов официанта только имитируются.

## Запуск

```bash
npm install
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Сервер разработки |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run preview` | Запуск собранной версии |
| `npm run data` | Обновляет `public/data/` из API |

## Скорость

Lighthouse, режим телефона (медленный 4G, замедленный процессор), главный экран. Замеры 1 ноября 2026 на рабочих адресах: ailillu.kz и этот сайт на GitHub Pages, по два запуска каждого.

| | ailillu.kz (Flutter) | Эта версия |
| --- | --- | --- |
| Оценка | 35–36 | 89–93 |
| Главный контент (LCP) | 41,3–41,4 с | 3,1–3,4 с |
| Блокировка интерфейса (TBT) | 3 000–4 600 мс | 0 мс |
| Загружено при старте | 15,1 МБ | 0,55 МБ |
| Запросов | 168 | 68 |

Самый тяжёлый экран, меню на 258 позиций при открытии по прямой ссылке (один запуск): оценка 87, LCP 3,5 с, 1,4 МБ.

Откуда разница:

- **Код:** основной бандл 82 КБ, экраны и карта грузятся только при открытии. Карта добавляет примерно 450 КБ, но только тем, кто её открыл.
- **Фото:** всё идёт через ресайз API (`Photo` в `src/ui/parts.tsx`). Фото, которое в оригинале весит 1,6 МБ, приходит как 17 КБ.
- **Длинные меню:** `content-visibility: auto` пропускает разделы вне экрана, строки обёрнуты в `memo`.
- **Первый экран:** список рисуется из статического `catalog.json`, затем обновляется из живого API.

## Как устроено

```
src/
  api/        запросы к API, типы, orders.ts (граница демо)
  domain/     чистая логика: каталог, меню, добавки, расстояния
  store/      app.ts: корзина, заказы, настройки; data.ts: каталог и меню
  nav/        стек экранов поверх истории браузера
  ui/         общие компоненты
  screens/    экраны
scripts/      сборка public/data перед деплоем
```

**Данные.** Тип заведения, теги и реальные способы заказа лежат внутри меню, а скачивать 160 меню ради одного списка нельзя. Поэтому `scripts/build-data.ts` собирает их при деплое. Сами меню всегда живые: приложение запрашивает их, когда гость открывает заведение.

**Копии заведений.** В API одно место часто заведено несколько раз: обычная копия, QR, Доставка, Kiosk. `buildCatalog` объединяет их в одну точку, а точки в сеть.

**Навигация.** Каждый экран и шторка соответствует записи в истории браузера, поэтому кнопка «Назад» на телефоне работает как в приложении. Экраны ниже верхнего не размонтируются: сохраняются прокрутка, фильтры и карта.

**Карта.** MapLibre и бесплатные тайлы OpenFreeMap, без ключа. Общий ключ Яндекса в код не попадает.

## Что не настоящее

- `submitOrder` в `src/api/orders.ts`: заказ остаётся на телефоне и в заведение не уходит. Настоящий заказ попал бы на реальную кухню, поэтому подключать его нужно к тестовому заведению или тестовому серверу. Заменить надо только эту функцию.
- Камера QR: вместо сканирования гость выбирает стол из настоящего списка столов заведения.
- SMS, Kaspi и вызов официанта: только интерфейс.
- Доставка показана как способ заказа, но оформить её нельзя.

## Деплой

`.github/workflows/deploy.yml` публикует сайт на GitHub Pages после каждого push в `main` и обновляет данные раз в сутки. В настройках репозитория нужно выбрать **Settings → Pages → Source: GitHub Actions**. Пути в сборке относительные, поэтому она работает и в подпапке GitHub Pages, и на отдельном домене.
